01 全局概览 Architecture

TaskPipeline 是一个面向研发交付流程的桌面端 Coding Agent 工作台。以任务看板为核心，串联 Jira 导入 → Agent 编排 → 代码评审 → MR 提交 → 合并跟踪的完整交付闭环。

Monorepo 依赖方向

Package Dependency Graph
依赖方向：desktop → pi-package → integrations → core。上层可以引用下层，下层绝不反向依赖。所有跨层通信通过依赖注入（DI）完成。

02 Pi 架构 Agent Runtime

Pi（@earendil-works/pi-coding-agent）是底层 Agent Runtime，提供会话管理、工具执行、Extension 加载等基础能力。TaskPipeline 通过两个路径使用 Pi：

🔌 Pi Extension（pi-package）

把 TaskPipeline 的任务体系（TaskStore / Git / Docker 沙箱 / 权限评估）封装为 Pi 的一个扩展包。Pi 会话启动时通过 DefaultResourceLoader 加载。

OpenAI 路径工具注册Docker 沙箱

🧩 Qoder Extension（pi-extension/qoder）

把 Qoder SDK 的完整能力封装为另一个 Extension。与 pi-package 平级，跑在 Electron 主进程同一 Node.js 进程中。

关键前提：Pi Extension 跑在同一 Node.js 进程内（Electron 主进程通过 resourceLoader 加载）。不存在跨进程问题——Extension 内可以直接 import 所有 API。

03 Qoder SDK 接入 Integration

项目的核心架构目标是把 Qoder SDK 的完整能力封装为一个 Pi Extension，而非仅作为 LLM Provider 使用。这使我们可以访问会话管理、HITL、Trace、子任务委派、MCP 注入、Skills 等全部能力。

Qoder SDK Integration Architecture

核心模块职责

模块 文件 职责
QoderOrchestrator pi-extension/qoder/qoder-orchestrator.ts 统一编排入口：管理 TaskAgent 单例、会话控制、状态探测、Review 调用、Auto-fix 循环
QoderTaskAgentDriver pi-extension/qoder/qoder-task-agent.ts TaskAgentDriver 的 Qoder 实现：runPlan / runImplementation / runTestGeneration 三阶段在同一会话内推进
QoderChatDriver pi-extension/qoder/qoder-chat-driver.ts ChatDriver 的 Qoder 实现：常驻会话、流式对话、MCP/Skills 注入、HITL 工具确认
QoderSession pi-extension/qoder/qoder-session.ts 封装 SDK query() 的 AsyncGenerator：消息分发、回合管理、Resume 锚点、流式去重
QoderTraceBuilder pi-extension/qoder/trace-builder.ts SDK 消息 → Trace Span 转换器：把 SDKMessage 实时转为 agent.run / tool.call 等 span

Scheme B：保留内部工具执行

为什么不用 Scheme A（纯 ExtensionAPI）？
Pi 的 ExtensionAPI 事件无法替代 SDK 的内部事件流（如 onMessage、canUseTool、会话 Resume 等）。Qoder SDK 必须在进程内保留 query() 的 AsyncGenerator 执行能力，由 Extension 包裹而非替换。这就是 Scheme B —— Extension 持有 SDK 的完整执行链路。

04 Task 处理 State Machine

任务处理是整个系统的核心。每个任务从 Jira 导入到最终合并，经历一条由状态机严格驱动的流水线。

状态转移图

Task State Machine — Full Transition Map

任务执行全流程

  1. 导入 & 确认：从 Jira 导入任务 → draft → 用户确认 → confirmed
  2. 环境准备：preparing 阶段创建 Git worktree，分配 feature 分支
  3. 计划生成：planning 阶段 Agent 分析任务，输出实施计划 JSON
  4. 计划审批：awaiting_plan_approval 用户审阅/修改计划后批准
  5. 代码实现：implementing 阶段 Agent 按计划修改代码（Qoder SDK 常驻会话）
  6. 校验：validating 执行 lint / test / build 命令验证代码质量
  7. 代码评审：reviewing 自动 Code Review，阻断问题进入 review_blocked
  8. 提交 MR：awaiting_commit → delivering 提交 GitLab Merge Request
  9. 合并跟踪：await_merge 等待 MR 合并完成 → completed

双运行时路由

系统支持两种 Agent 运行时，通过 runtimeProvider(task) 动态路由：

⚡ Qoder 路径（主路径）

常驻会话，三阶段（Plan / Impl / Test）在同一 Qoder Session 内按回合推进。支持 Resume、暂停、HITL 工具确认。

05 Chat 子系统 Driver Pattern

对话系统采用 Driver 抽象模式，上层 ChatService 不感知底层 SDK 细节。

前端 UI ChatPage → IPC chat:startStream → 渲染 StreamChunk
ChatService 编排层：取 Driver → 翻译输入 → 转发 Chunk → 持久化 → 记忆注入
DriverRegistry ChatDriverRegistry → 按 driverId 路由到 QoderChatDriver / OpenAIChatDriver
QoderChatDriver QoderSession → SDK query() → AsyncGenerator<SDKMessage>
存储层 ChatStorage (SQLite) — 按 driverId 各自序列化/反序列化
ChatDriver 接口契约：listModels() · streamChat() · serializeUserMessage() · serializeAssistantMessage() · deserializeMessage() · dispose()。每种 Driver 自带消息序列化能力，存储层只存 raw JSON。

06 Trace 可观测性 Observability

系统提供端到端的 Agent 执行 Trace 回溯能力，是项目的核心特色之一。

📊 TracePipeline

内存中的 Trace 总线：管理 Trace 生命周期（begin → active → end）、Span 栈、事件分发。支持 Task 和 Chat 两种 Trace 类型。

🔄 QoderTraceBuilder

SDK 消息 → Span 转换器。监听 onMessage 钩子，把 SDKMessage 实时转为 agent.run / tool.call / llm.call 等 Span。

💾 JSONL 持久化

每个 Trace 对应一个 .jsonl 文件，逐条追加 Span 事件。支持应用重启后加载历史 Trace。

🖥️ 前端 Trace 页面

瀑布图 / 时间线展示完整的 Agent 执行过程：LLM 调用、工具执行、子任务嵌套、Token 消耗等。

07 总结：关键设计决策 Key Decisions

🧩 Extension 化而非硬编码

Qoder SDK 以 Pi Extension 形式接入，而非硬编码在 main.ts 中。运行时行为不变，但代码组织清晰、可独立测试。

🔌 Driver 抽象

Chat 和 Task Agent 都采用 Driver 模式。上层编排逻辑不感知底层 SDK 细节，后续接入新 Agent 运行时不需要重写上层。

📊 状态机驱动

任务状态转移由 core/workflow.ts 的纯函数表严格定义。任何非法转移直接抛错，杜绝状态混乱。

💉 依赖注入

所有模块通过 DI 获取依赖（initTaskLifecycle(deps)、QoderOrchestrator(deps)），避免循环引用，便于单测。

🔄 会话持久化

Qoder 会话支持 Resume：应用重启后通过 sessionId 恢复上下文，多轮对话/任务不丢失。

📡 端到端 Trace

Task 和 Chat 两条路径都有完整的 Trace 采集。JSONL 持久化 + 前端瀑布图，支持任意时刻回溯 Agent 的完整执行过程。

一句话总结：TaskPipeline 以 Pi 为底层 Agent Runtime，通过 Extension 体系接入 Qoder SDK 的完整能力（会话/HITL/MCP/Trace），用状态机驱动的任务流水线串联从 Jira 导入到 MR 合并的研发交付闭环，并提供端到端的可观测性回溯。
